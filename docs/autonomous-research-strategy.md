# R4 Autonomous Research Strategy

## 연구 근거와 등록

R1의 기준선 대비 낮은 적중률, R2의 H5 상승 오탐 및 마스크 실패, R3의 H1 개발 이득 역전과 H20 앵커 부족에서 출발했다. R2 Feedback과 R3 AnalysisStore의 원래 실험·체크포인트를 검증했다. Phase D는 별도 보존된 publication SHA와 검증 스키마로 확인했다. 그 연구의 결과를 R4의 점수로 사용하거나 남은 108개 슬롯을 실행하지 않았다. R4는 Phase D의 원본 증거 키·콘텐츠 해시, 기존 후보 검증, Compact Evidence 및 CPU 전용 로컬 Ollama 공급자를 재사용한다.

R3와 같은 KRX 소유 자료에서 학습 16종목, 개발 8종목, 고정 평가 8종목을 분리했다. 학습은 2022-01-03~2023-06-30, 개발은 2023-08-01~2023-12-28, 고정 평가는 2025-09-01~2026-06-30이다. 두 개발 종목 그룹은 사전 등록한 정렬 순서에서 번갈아 4개씩 배정했다. 두 시간 블록은 2023-08-01~10-13과 2023-10-16~12-28이며 블록 끝을 넘는 라벨을 제외했다. 종목군과 시간 블록을 각각 평가했다. R3의 지연 관측 종가 라벨, 20bps 중립 밴드, 0.5 방향 임계값을 적용했다. R3이 이미 노출한 고정 구간은 R4 내부 비교에 한정하며, 정책을 동결한 후 읽었다.

| 군 | 후보 선택 | 개발 최종 선택 |
| --- | --- | --- |
| A | 기존 Python 순위 규칙 | R3의 BA/Accuracy/AP/Brier 및 H5 방향 조건 |
| B | A와 동일 평가 재사용 | 종목군·시간 블록 안정성 |
| C | Python 순위에 자체 최신 결과와 검증된 R3 실패·비용 반영 | B와 같은 안정성 규칙 |
| D | 첫 선택에 Compact Gemma 제안 최대 1회, 유효하면 다음 선택부터 자기 결과로 C와 동일하게 진행 | B와 같은 안정성 규칙 |

H1/H5의 각 군·기간에 공통 R3 시작 모델 2개와 후속 후보 최대 2개를 사전 등록했다. D는 H1 한 셀로 제한했다. 동일 후보 수와 논리적 검색시간 100초를 각 셀에 적용하며 D의 로컬 추론 시간도 계산한다. B의 탐색은 A에서 이미 평가했고 비교 시 A의 검색시간을 함께 표시한다. C/D의 후보가 이전 군과 겹치면 선택을 먼저 기록하고 정확한 동일 구성 결과를 재사용한다. 각 군은 동료 군의 미선택 결과, 캐시 상태 및 고정 평가 결과를 후보 선택에 사용하지 않는다. 최대 신규 fit은 10회다. 더 큰 60~120 후보 창에 대한 별도 승인은 사용하지 않았다.

안정성 규칙은 R3의 기존 표본 기준과 비중첩 앵커 기준을 각 종목 그룹 및 시간 블록에 적용한다. 전체 BA 개선은 최소 +0.5%p이며 Accuracy·AP·Brier 비열화와 H5 FPR/Recall 가드를 유지한다. 각 적격 그룹과 블록에서 BA·Accuracy·Brier 및 방향 조건을 통과할 도전자가 없으면 Legacy를 유지한다. 불충분한 표본에서는 후보를 강제로 선택하지 않는다.

## 실행 및 조회

요청 버전은 `autonomous_strategy_request_v1`이다. 비공개 요청에 `r3_root`, `r3_plan_pin_file`, `phase_d_publication`, `phase_d_hash_file`, `local_model_digest`를 제공한다. 보고서·PIN은 서로 다른 새 비공개 디렉터리에 보존한다. 보고서 조회에는 새 출력 이름을 사용한다.

```sh
umask 077
dsv autonomous-research autonomous-strategy-register --root "$R4_ROOT" \
  --pins-root "$R4_PINS" --request "$R4_REQUEST" --request-pin-file "$R4_REQUEST_PIN"
dsv autonomous-research autonomous-strategy-run --root "$R4_ROOT" \
  --plan-pin-file "$R4_PINS/plan.pin"
dsv autonomous-research autonomous-strategy-report --root "$R4_ROOT" \
  --plan-pin-file "$R4_PINS/plan.pin" --report "$R4_ROOT/report.json"
jq '.shortlist.arms' "$R4_ROOT/report.json"
jq '.result.fixed_evaluation[] | {cohort, horizon, results: [.comparisons[] | {arms, paired}]}' \
  "$R4_ROOT/report.json"
```

실패한 실행의 계획, 후보와 Gemma 판정을 이어 사용할 때에는 새 출력 디렉터리로 등록하고 비공개 요청에 `recovery.root`와 `recovery.plan_pin_file`을 지정한다. 복구는 동일한 연구 설계와 패키지 버전, 실패한 작업자, 동결 전 상태, 원본 DB와 체크포인트 무결성, 동일 학습·개발 모집단을 확인한다. 이번 복구에서는 H1 실험 3건과 거절된 Gemma 호출을 원래 식별자로 재사용했다. 원본 로그, Evidence Pack과 제안 검증 아티팩트를 보존했다. 비공개 `execution-bundle`에는 두 실행의 원본 소스 아카이브, 구현 해시, PIN, DB·보고서·로그·체크포인트 해시를 기록한 명세가 있다.

## 2026-11-27 실행 결과

상태는 **PARTIAL**이다. 승인된 과거 KRX 데이터에서 신규 구성 6개를 실제 적합했다. 개발 예측은 H1 모델당 680행, H5 모델당 720행으로 4,200 모델–행을 저장했다. 별도의 고정 비교는 두 코호트에 걸쳐 H1 926행과 H5 914행을 사용했다. 고정 평가는 코호트당 비중첩 앵커 H1 55개, H5 23개였다. 개발 모집단에서는 H1 중립 112행·미성숙 라벨 16행, H5 중립 40행·미성숙 라벨 48행을 제외했다. 각 셀에서 후속 후보 2개씩을 비교해 A/B/C 관점에서는 평가 12건이다. 그중 B의 4건은 A의 평가를 공유했다. C는 A와 겹친 H1·H5 후보를 각 한 번씩 정확 캐시로 재사용했다. 첫 작업자의 H1 적합 3건은 복구 단계에서 재적합 없이 사용했다. 후보 적합·평가 실패는 0건, 작업자 실패와 Gemma 거절은 각 1건이다.

| 기간 | 군 | 첫 번째 후속 후보 → 두 번째 후속 후보 | 최종 선택 |
| --- | --- | --- | --- |
| H1 | A, B 공동 탐색 | HistGradientBoosting(15), Daily+Weekly → Logistic Regression(C=10), Daily | A는 보존된 R3 도전자, B는 Legacy |
| H1 | C | Logistic Regression(C=10), Daily → Logistic Regression(C=0.1), Multi | Legacy |
| H5 | A, B 공동 탐색 | HistGradientBoosting(15), Daily+Weekly → RandomForest(32 trees), Daily | A와 B 모두 Legacy |
| H5 | C | Logistic Regression(C=10), Daily → HistGradientBoosting(15), Daily+Weekly | Legacy |
| H1 | D | Compact Gemma 호출 1회, 추론 시간 초과로 REJECTED | 평가 없음 |

C는 비교용 기존 순위와 4건 중 3건에서 다른 후보를 골랐다. 근거가 연결된 우선순위 하향 사례는 H1의 과거 동계열·동일 마스크 모델의 낮은 구간 BA, H5의 과거 방향 가드 및 구간 BA 실패였다. 선택된 후보 및 기존 순위 최상위 후보의 감점은 0이었다. 이들의 순서 변화에는 Compact에서 재사용한 정보 가치와 비용 점수가 작용했다. C는 각 첫 후보의 실제 평가를 받은 후 두 번째 결정을 내렸고, 후속 실험의 부모 ID와 각 선택·제외 근거를 남겼다. 동결 후 개발 자료로만 두 번째 선택을 다시 계산했다. 첫 후보 성적의 유무에 따라 순위 근거는 달라졌지만, 두 번째 후보의 ID는 H1과 H5에서 모두 같았다. 이번 실행에서 새 결과가 후속 후보를 바꿨다는 증거는 없다. H5 C의 첫 후보는 개발 FPR을 53.64%에서 44.85%로 낮췄지만, 상승 Recall은 60.26%에서 45.64%로 낮아졌다. H1 신규 3개는 전체 BA와 Accuracy가 올랐으나 모두 Brier가 악화됐다. 신규 H5 3개는 전체 BA가 모두 낮았다. 최소 개선을 충족한 신규 후보는 0건이다.

H1 B/C는 A 대비 각각 22건·4건을 더 맞혔다. Legacy의 FPR은 A의 57.97%·43.08%에서 42.71%·30.26%로 줄었다. 상승 Recall은 53.72%·41.24%에서 44.21%·30.41%로 줄었고 AP도 낮아졌다. H1 Legacy는 학습 사전확률·다수 클래스 기준선보다 첫 코호트에서 19건 적게 맞혔고 둘째 코호트에서는 동률이었다. H5 Legacy는 세 전략에서 같았다. R3의 24종목 H5 도전자보다 첫 코호트에서 4건 적게, 둘째에서 4건 더 맞혔다. 두 H5 코호트에서 모멘텀보다 41건·5건 더 맞혔으며, 사전확률·다수 클래스 기준선 대비 −8건·+4건이었다. 전 기준선, FPR·FDR·상승/하락 Recall, 개별 가격·라벨 및 제외 사유는 비공개 보고서에 보존했다.

신규 6개 적합 시간 합은 16.77초, 적합·개발 예측·평가 합은 19.07초다. A/C의 후보별 원실행 시간을 합하면 H1 8.00/1.90초, H5 8.89/8.50초다. H5 복구 작업자 내의 탐색은 A 9.01초, C 1.22초였으며 C는 두 번째 후보를 정확 캐시로 얻었다. 캐시 적중과 복구 비용이 섞인 실행시간이어서 같은 시간으로 더 많은 독립 후보를 검증할 수 있는지는 추가 검증이 필요하다. Python 작업자 시간은 첫 시도 21.07초, 복구 35.42초, 각각 최대 RSS 272,408/332,188 KiB였다. Gemma 1회 비용은 75.56초로 적격 제안, 평가, 대체 실행이 각각 0건이었다.

R5에서 사전 등록할 수 있는 비교 기준은 H1/H5의 기존 Legacy다. R4 신규 도전자 중 독립 검증에 앞서 지지할 모델은 없었다. H20은 R3 개발 앵커 4개, 두 고정 코호트 각각 7개로 근거가 부족했다. 보호된 Q3와 Final Test는 봉인 상태를 유지했다. PIT 적격성, 독립 미래 성능, Performance Approval 및 매매 승인은 모두 미확립 상태다.
