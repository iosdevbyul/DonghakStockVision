# Operational signal publication preflight

Phase 3 uses a conservative, read-only preflight before any approved per-security inference publication. This does not run a model, enroll research-only HGB artifacts, issue review approvals, or write results.

`inspect_publication_inputs(source, approval)` reports:

- `readyForManualReview`: basic input structure and receipt consistency have been checked
- `publicationAuthorized`: **always false**; a JSON receipt cannot authenticate an independent reviewer
- `candidateRecords`: records in the supplied operational PIT export
- `sourceSha256`: hash of the input bytes, or null
- `blockers`: explicit reasons such as absent exports, non-operational scope, unregistered inputs or unverifiable reviewer signature

**Do not equate readyForManualReview with production approval.** The existing `publish_approved_signals` converter remains a manually controlled boundary, not a runner or a cryptographic trust service. Actual nonempty inference requires an independently approved operational model registry, trusted locally pinned checkpoint, reviewed PIT dataset/features/cutoffs, signed second-person approval, and a real exporter. Current research-only HGB checkpoint contracts cannot be promoted implicitly.

Future work: define authenticated approval receipts and an authorized artifact registry, then build/test an operational PIT inference runner using explicitly qualified operational artifacts. No actual user stock predictions are generated by this PR.
