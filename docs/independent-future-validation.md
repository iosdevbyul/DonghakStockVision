## 반복 조회와 감독 운영

같은 `direction-shadow` CLI를 사용한다. 기존 등록 요청에 R3 모델 참조를 사용할 경우 `root`, `plan_pin_file`, `experiment_id`와 함께 원래 `result_id`, `database_sha256`을 제공한다. 기존 v3 요청 문서와 출력/PIN 분리 규칙을 유지한다. 파일은 새 이름으로 생성하고 원래 등록과 Forecast 저널은 고정한다.

```sh
dsv direction-shadow preflight --request "$REQUEST" --request-pin-file "$REQUEST_PIN" \
  --report "$CHECK" --report-pin-file "$CHECK_PIN"
dsv direction-shadow audit --request "$REQUEST" --request-pin-file "$REQUEST_PIN" \
  --journal "$JOURNAL" --head-pin-file "$HEAD_PIN" \
  --report "$AUDIT" --report-pin-file "$AUDIT_PIN"
```

승인된 운영 자료와 기존 계약이 적격할 때의 `record`, 신규 관측을 기존 저널에 연결하는 `resolve`, 불변 자료에서 새 스냅샷을 만드는 `report`, 중복 처리 및 복구 명령은 [#250 Shadow 명령](prospective-direction-shadow.md)을 사용한다. 연구용 조회는 현행 `/api/v1/research/predictions`와 그 아래 `/models`, `/comparisons`에 연결한다. 새 R5 행은 승인된 publication에서 실제 종가와 결과 상태를 제공한다. 원본 관측 IDs, 경로와 PIN은 사적 audit에 보존한다. 보호 Final Test와 Q3 기록, 기존 수집 일정, 저널, 운영 상태와 승인 플래그를 유지했다. 향후 수집 권한 조정, 독립 시간 증거 연결, R6 유한 감독 운영에는 기존의 별도 승인이 필요하다.
